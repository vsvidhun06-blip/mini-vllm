# Reward diagnostics (Phase 4)

Generated by `scripts/eval/repair/rule_only_ablation.py`. Do not hand-edit.

## Why this file exists

Reward v1 was degenerate on real hardware: `docs/eval/raw/adaptation/decisions_042.csv` shows exactly two reward values across an entire run (0.8 then 0.3 forever), because all four terms saturated simultaneously. Aggregate statistics hid it. This diagnostic makes the failure impossible to miss: it evaluates every candidate arm on every workload and reports the reward spread, failing loudly if the reward cannot tell configurations apart.
